# Backend validation

Use [acceptance traceability](../../../docs/traceability.md) and the task's own observable criteria. A passing document check or fixture test does not establish a provider integration or native OS behavior.

P1-01 established workspace checks; P1-02 adds the generated-contract gate. Run `cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo test --locked --workspace`, `./scripts/check-core-boundaries.sh`, and `./scripts/test-check-core-boundaries.sh`. On hosts without desktop system libraries, CI excludes `quotavista-desktop` from Linux Clippy/tests and checks the full workspace on macOS. Run `cargo run --locked -p quotavista-contracts --bin generate-contracts -- --check` without regenerating first when verifying committed contract freshness; the check must fail for missing or modified output. Regeneration is a separate intentional step.

Prioritize meaningful tests for overflow, decimal precision, DST boundaries, missing versus zero, transaction rollback, candidate publication, stale generations, crash recovery, and session-only restart. Use injected clocks, synthetic provider identities, temporary application directories, and failure-capable fake stores. Never read a contributor's real credentials in tests.

Native Keychain/Secret Service and window/tray/notification checks require separate evidence with OS version, architecture, Linux session type, exact procedure, and result. Keep G01/G02/G04 open until their stated evidence exists. Record benchmark measurements rather than estimates.

P1-13 made that requirement concrete with two committed scripts. Use them instead of inventing a procedure for each native task:

- `./scripts/native-checks.sh --environment` records the host: OS version and build, architecture, `XDG_SESSION_TYPE` / `XDG_CURRENT_DESKTOP` / GNOME Shell version on Linux, pinned toolchain versions, and `gdbus` probes for `org.kde.StatusNotifierWatcher` and `org.freedesktop.Notifications`. `--automated` runs the host-independent lifecycle, capability, and IPC-boundary suites. `--interactive` walks a human through the sixteen desktop observations and prints `OBSERVED: PENDING (no interactive terminal; run this step manually)` when there is no terminal; it never guesses a pass.
- `./scripts/native-launch-probe.sh` launches the desktop binary for real and asserts only what a headless caller can prove: exec-to-capabilities latency, the `quotavista: capabilities tray=… notification=…` line, single-instance handover, a field-by-field validation of the committed synthetic fixture, warm-restart identity, and `QUOTAVISTA_TRAY=off` reporting `tray=Unavailable` only when that launch's diagnostics are clean and its own fresh fixture validates. Everything else gets an explicit `NOT OBSERVED: …` line naming the interactive step that covers it, so a green probe cannot be misread as desktop usability.
- `./scripts/native-launch-lib.sh` holds the shared isolation and detection helpers; `./scripts/test-native-launch-probe.sh` is their regression suite. The main-path cases launch a synthetic test double and never the real binary. Run the suite after changing either script — it builds SQLite fixtures on the real migrations, so a validator that stops rejecting a half-seeded store fails there rather than in a native run.

Honesty and safety rules those scripts encode, and that any new native evidence must keep:

- A `SIGTERM` exit (status 143) from the probe is **not** the tray Quit path and is not evidence for it. Say so in the record.
- Each launch gets its own `mktemp -d` `TMPDIR`, so the default prototype state directory `${TMPDIR:-/tmp}/quotavista-prototype` is never created, read, modified, or deleted; `ls` on it before and after is part of the evidence.
- Overriding `TMPDIR` does **not** isolate the single-instance channel. `tauri-plugin-single-instance` derives it from the application identifier alone — `/tmp/<identifier with . and - as _>_si.sock` on macOS, the session D-Bus name `<identifier>.SingleInstance` on Linux — so a fresh `TMPDIR` configures only the process you start and an already-running incumbent can still receive the activation, show its window, and run its wake path against its own state. Launch validation runs under a distinct identifier (`TAURI_CONFIG='{"identifier":"…nativeprobe"}'` with its own `CARGO_TARGET_DIR`), fail closed if either channel has a live holder or either binary is running, and refuse to run at all when you cannot tell a live socket from a stale one. Detect incumbents with `lsof` holders and `ps` argv matching, never by connecting to the socket — connecting *is* the activation. A loose `pgrep -f <product>` matches any process whose environment merely contains the checkout path.
- Reading a store back is not validating it. A check whose whole criterion is "cold equals warm and non-empty" passes an empty schema and a half-seeded one alike; assert the deterministic fixture identities, counts, relationships, revision and settings, and fail on the seeding and credential-store diagnostics instead of printing them. Expect the lifecycle to change across a restart (`active` when seeded, `needs_credentials` afterwards, because startup credential reconciliation cannot read a session-only secret), so the expectation is per-launch rather than a constant.
- Counts are not content. A corruption that preserves every aggregate — six facts, two published partitions, revision 8 — can still attach facts to another scope's partition or flatten their values, so assert relationships and content on the same rows (scope identities, facts joined to a partition of a *different* scope, published partitions pointing at another partition's run, per-scope fact and partition counts, and that each scope's amounts are distinct, numeric, positive and contiguous). Pair every such check with a negative fixture that keeps the aggregate identical and must still be rejected.
- An unchanged filesystem stamp is not proof that nothing activated. Connecting to an existing Unix socket need not change its mtime, so "the stamp did not move" supports only "no recorded change". The substantive guarantee is a disjoint application identifier, which makes the two channels different by construction; say which one you are relying on.
- Inspect the channel the platform actually uses, and fail closed when you cannot. On Linux the single-instance channel is a session-bus name, not a socket in `/tmp`, so a socket-only detector reports "clear" there no matter what is running; `org.freedesktop.DBus.NameHasOwner` answers ownership without claiming the name. A state that cannot be interpreted — no `lsof`, no `gdbus`, a bus that will not answer — is an incumbent, never a clear host, and the run refuses rather than guessing. The same split applies after launch: on Linux the validation name must be owned on the launched process's own session bus (`gdbus --address` of that process's `DBUS_SESSION_BUS_ADDRESS`, never the caller's bus); a free or unknown answer fails, and a missing `/tmp` socket is not a failure there. On macOS the post-launch evidence remains the validation socket appearing.
- A pre-flight check is not a lock. A fixed validation identifier is shared by every run on the machine, and two worktrees of this repository share `/tmp` while having separate `target/` directories, so take an atomic `mkdir` lock and release it on every exit path including the refusals. Never unlink a channel another process holds.
- Verify a binary's identity by reading it back out of the file, not by trusting the build command that was supposed to produce it. A cached artifact under a `--skip-build` shortcut can carry the ordinary identifier, and a post-launch identity check cannot undo an activation that already happened.
- A command the procedure tells an operator to copy must be executed by a test, not just asserted as text. A substring check passed a mis-nested `mktemp` template that created nothing.
- Every scripted launch sets `QUOTAVISTA_SECRET_STORE=session-only`. The production Keychain/Secret Service name is `quotavista` (`crates/infrastructure/src/secrets.rs`), which does not satisfy the `quotavista-test-` prefix rule, so the prototype is never launched against the native store during validation. Native-store evidence comes only from the `#[ignore]`d smoke tests under a disposable `quotavista-test-<task>-<pid>` service, with cleanup verified independently of the test (`security dump-keychain | grep -c 'quotavista-test'` → 0 on macOS, `secret-tool search service <name>` on Linux).
- Do not manufacture a "locked store" observation by locking the operator's own login keychain. Cite the automated `Locked`-versus-`Unavailable` tests and mark the row partial.
- A successful build is never desktop usability, and a CI runner is never a native target: `ubuntu-latest` is headless and excludes `quotavista-desktop` from Clippy and tests, and `macos-latest` is an unnamed image that only builds.
- `docs/validation/native-target-procedure.md` is the operator procedure; `docs/validation/phase-one-exit-assessment.md` is the gate decision. Update both when new native evidence lands, and keep a row for an unavailable target as `UNVERIFIED` rather than "expected to pass".

The 100,000-fact local query benchmark (P1-12) is env-gated in `apps/desktop/src-tauri/src/benchmark.rs`: run `QUOTAVISTA_BENCHMARK=1 cargo test --locked -p quotavista-desktop statistics_query_mix_benchmark -- --nocapture`. It seeds ninety settled days at exactly the 100,000-fact storage bound through the repository write path, measures the statistics/overview query mix through the same `run_request` wire path the renderer uses, and writes a JSON artifact (five warmups, at least thirty measured queries, per-mix and overall p50/p95/max, cancellation behavior, failures). A target miss is recorded, never asserted away; the committed artifact lives with the task's validation record.
