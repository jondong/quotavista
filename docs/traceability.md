## P1-04 prototype evidence

Scope: the P1-04 task branch on macOS arm64, Rust 1.99.1, SQLx 0.9.0, bundled SQLite 3.51.3. Every journal, ledger, database, and secret store in the fixtures is synthetic and lives in a throwaway `TempDir`; the secret store is a fake in-memory map, so no native store, keychain, application-data directory, production, business, or personal database was opened, read, or written. Commands, per-criterion evidence, and remaining gaps are recorded in [the task validation record](../.trellis/tasks/archive/2026-10/10-18-p1-04-recovery-fences/validation.md).

- A18: injected interruptions before the journal write, after candidate activation, and during cleanup either converge idempotently or stay visibly pending: a durability failure before the first journal write leaves no secret, projection, or lifecycle change; a locked secret store compensates the orphan candidate and never acknowledges; a failed post-commit cleanup leaves `compensation_pending` and recovery repeats the same pending report until the store unlocks. Recovery runs before any mutation or scheduling, removes an orphan candidate the projection never recorded, and one locked connection does not stop recovery for the others. Unparsable or truncated journal and ledger content refuses to open a coordinator, so absent readable state is never read as finished cleanup. A rotation whose candidate is the reference the connection already holds is refused before any journal, projection, or secret write, so compensation can never remove a secret still in use, and a reused operation identifier for a different connection is refused before it can make the journal undecodable. Session-only restart semantics, real provider identity verification, and the credential UI remain pending.
- A20: the deletion ledger is durable before the lifecycle transition, fences dispatch and result writes, and rejects a restore manifest carrying a deleted opaque identifier even after a simulated restore of an earlier database backup whose projection no longer knows the deletion. A failed cleanup does not acknowledge the deletion: the entry stays `pending_cleanup`, scheduling and every restore stay blocked, and the operation is retryable across a restart. A deletion interrupted after its `deletion_pending` transition and before its journal record does not dead-end either: the caller may begin the deletion again, and recovery resumes it from the ledger entry alone, removing the reference the database names and then acknowledging the cleanup. A deletion whose transition was refused, or never committed, is not owed: the ledger is written first, so recovery leaves the row's credential and the `pending_cleanup` entry untouched and the deletion stays retryable. Managed backup creation, purge, and restore execution, retention purges, the local fact purge during deletion, and release deletion certification remain pending.
- A21: journal and ledger files carry opaque identifiers and nonsecret state only; a fixture asserts that no credential value, provider identity, alias, provider account key, or usage metric appears in either file. Failure to establish durability stops the mutation before any secret write. Native secret stores, session-only memory guarantees, and restricted IPC authorization remain pending in P1-05 and P1-07.
- A23: an obsolete generation cannot commit: the final generation, lifecycle, and fence check runs inside the `BEGIN IMMEDIATE` write transaction, and a stale context rolls back with the candidate reference compensated. `set_lifecycle` re-checks the same incomplete-projection fence inside its own write transaction, and scheduling admission consults database projections as well as the external journals, so an operation whose journal record was released but whose projection could not be completed still fences a lifecycle mutation, a dispatch, and a result write. Statistics throughput benchmarks, async desktop integration, and native disk-full behavior remain pending.


## P1-05 prototype evidence

Scope: the P1-05 task branch on macOS arm64 (mac-mini, macOS 27.0.1), Rust 1.99.1, keyring-core 1.0.1 with apple-native-keyring-store 1.0.2 and dbus-secret-service-keyring-store 1.0.1 (all pinned). Backend fixtures use fake stores, throwaway `TempDir` journals, and synthetic SQLite databases. The macOS native smoke check ran once against the host login keychain with disposable synthetic secrets under the uniquely named test-only service `quotavista-test-p1-05-<pid>` and removed every test entry afterwards; no other keychain entry was read, modified, or deleted. Commands, host and cleanup evidence, per-criterion fixtures, and remaining gaps are recorded in [the task validation record](../.trellis/tasks/archive/2026-10/10-18-p1-05-secret-stores/validation.md).

- A10: synthetic secret values never reach the journal, the ledger, or any SQLite file (including WAL sidecars); a fixture asserts their absence while opaque `qv1:<backend>:<opaque>` references and nonsecret configuration are present. Error and reference validators reject secrets without echoing the rejected value, and store errors carry no platform payload or secret content. Contract DTOs and user-facing messages were unchanged and still carry no credential values.
- A18: a locked store during the candidate write keeps the previous active credential in place and retrievable; when the commit succeeds but removing the superseded reference fails, the operation stays pending compensation in the journal across a simulated restart until recovery completes the cleanup. The native macOS roundtrip preserves the previous entry until the new candidate commits. Real provider identity verification during rotation remains pending with the providers.
- A21: locked and unavailable are distinct errors end to end and never move the connection or fall back to file or plaintext persistence — no such fallback path exists. The session-only store keeps values in process memory only; after a simulated restart the nonsecret configuration is retained, the session secret reads back as needs-credentials, and reconciliation transitions the connection to `Needs credentials` without writing anything to the store. Native Linux Secret Service smoke evidence remains pending (no session bus on the validation host; the non-destructive check is in place), and restricted IPC authorization remains pending in P1-07.

## P1-06 prototype evidence

Scope: the P1-06 task branch on macOS arm64, Rust 1.99.1, SQLx 0.9.0, bundled SQLite 3.51.3. Every fixture is synthetic: throwaway `TempDir` SQLite databases, an in-memory durable store behind the `DurableStore` port, a manually advanced fake clock, and the in-repo simulated adapter. The providers crate carries no network dependency, and no real endpoint, credential, or account was contacted. Commands, per-criterion evidence, and remaining gaps are recorded in [the task validation record](../.trellis/tasks/archive/2026-10/10-18-p1-06-simulation/validation.md).

- A05/A06: ten deterministic adapter scenarios keep real zero, unknown, stale-upstream, missing-token, partial-permission, rate-limit, incomplete-replacement, no-history, and withdrawn-terminal-attestation states distinct; a job whose token dataset fails with `PermissionRequired` while its spend dataset succeeds retains the previously committed token snapshot and records the two dataset health entries independently. Offline, timeout, and invalid-response failures arrive as typed errors; no real provider behavior is claimed.
- A07: fake-clock coordinator tests show manual-only mode (`refresh_minutes: None`) admits nothing and issues no implicit launch/wake/recovery query; with an interval set, a connection is re-admitted only after the configured minutes since its last completion; persisted cooldown boundaries are written durably before adoption, survive a restart, only move later, and block manual admission until expiry; a second manual request coalesces with the live job and cancellation frees the concurrency slot immediately.
- A16/A17/A19: history staging runs through bounded candidate pages with cursor compare-and-swap; a stream that never attests completeness is cut off at the page bound, ends incomplete, keeps its partial candidate separately addressable, and cannot replace the published partition.
- A18: a synthetic response arriving after the connection is disabled or moved to `deletion_pending` is fenced by the generation re-check inside the write transaction and ends the job without overwriting committed values.
- A22: page staging enforces the P1-03 bounds (previous cursor must differ, at most 1,000 facts per page and 100,000 per candidate) and cooldown records fail closed on corrupt input; bounded history (100 pages / 30 seconds) caps provider-driven work per job.

## P1-09 prototype evidence

Scope: the P1-09 task branch on macOS arm64, Rust 1.99.1, Node 24, SQLx 0.9.0, bundled SQLite 3.51.3. Every fixture is synthetic: throwaway `TempDir` SQLite databases, the in-repo simulated adapters behind a routing `SimulatedRouter`, session-only secrets, and recorded change sinks. No real endpoint, credential, account, keychain entry, or application data directory was touched. Commands, per-criterion evidence, and remaining gaps are recorded in [the task validation record](../.trellis/tasks/10-18-p1-09-overview-statistics/validation.md).

- A05: real zero, unknown (missing), stale, unsupported, and collection-gap states stay distinct end to end — a fixture with a `Zero` scenario snapshot renders `0` while a missing snapshot renders as `unknown` text with its reason, an unsupported Kimi-style quota on OpenRouter renders as `not supported by this source` in both locales, and an empty series draws an explanation instead of an all-zero line.
- A13: the aggregation engine derives Monday-start weeks and half-open day/week buckets from the P1-02 calendar helpers; range validation rejects reversed, overlong (> 366 days), and future ranges with typed errors before any read; the current period is clipped at a single captured as-of and marked provisional; UTC-only source buckets render in their own labeled lane and are never split into local-zone days.
- A14: recorded totals sum only published usage facts through checked `u128` arithmetic; current snapshots never enter range totals (account/key representations are not added twice), and `TokenFact::recorded_total()` adds only `Additional` subcounts, never `Included` or `Unknown` ones. When no compatible fact exists the recorded total is null, not zero.
- A15: the deterministic two-provider fixture yields exact expected sums (1,234,567,890,123 + … and 9,876,543,210,987 + … bucket series) per scope, Kimi's shared-quota ratio/percentage-point metrics stay visible next to OpenRouter's Credits-style spend, and each plan row carries its native unit with its own source timestamps.
- A17: per-bucket coverage distinguishes complete, not-yet-settled (provisional current period), outside-lookback, and collection-gap; history holes render as gaps, never as a zero line, and the renderer's empty chart shows an explanation.
- A22: invalid dates, reversed ranges, unknown zones, overlong ranges, and future end dates fail with the sealed validation error before any side effect; the statistics read pre-counts facts and fails with `ResourceLimit` above the 100,000-fact bound instead of truncating.
- A25: both catalogs carry the 99 keys with matching placeholders (`npm run i18n:check`), the statistics screen keeps the selected preset, grain, and custom dates across a language switch (state is not keyed by locale), and range totals format through BigInt grouping in the display locale while boundaries stay in the reporting zone.

Remaining gaps: no live usage totals, no estimation from balance/quota differences, no provider completeness claims, and no retention/backfill engine (all out of scope by design); the 100,000-fact throughput benchmark remains pending for P1-12; native GUI behavior of the seeded demo window was not exercised in this round.

## Release evidence rules

- A01 and A03 require real-account reconciliation; fixtures alone cannot pass them.
- Synthetic data is appropriate for numerical boundaries, failure injection, revision logic, and alert timing. Describe it as synthetic evidence.
- Provider-specific capabilities remain gated until measured; explicit Unsupported is honest behavior, but it does not automatically satisfy a required unavailable core metric.
- Bilingual key parity is necessary for A25, but both languages still need runtime interaction checks.
- English documentation can pass its current document check while A24's final release audit remains pending.
- Each future verification entry should record criterion, build or commit, environment, method, result, and any gap. Do not replace Pending with Passed based on a design walkthrough.
